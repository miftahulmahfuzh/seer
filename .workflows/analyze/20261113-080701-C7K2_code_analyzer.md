## Detailed Requirements Understanding

**Problem.** `lab run` simulates every arm, then `twins.repeats` compares each finished curve with the record. A control arm is a declared repeat (`twins.declaration`: role control), so it is accepted. Measured today (this session, `twins.for_method` on the committed lab): M0545-SMA200 = M0084-MONTHLY (trial 349), M0545-ALWAYS = M0084-ALWAYS (347), M0561-D3 = M0558-A3 (2011), M0561-D6 = M0558-A6 (2012), M0606-SHALLOW20-NOGATE = M0108-DD20 (342), M0606-DRAW20-GATE-S1 = M0232-PLC1 (775), M0606-DRAW20-GATE-S2 = M0313-GDRAW-S2 (1076), M0606-EW20-DV-GATE = M0337-DVOL (1159): eight arms, all first-recorded by an earlier method. The brief's claim holds. (M0561's D3/D6 are not control-role arms by the "Control:" opener necessarily; they were still accepted because their rationale names M0558.)

**Reuse or recompute.** A recorded trial already holds the curve, metrics and trade count the re-run would recompute, byte for byte (that is what a twin *is*). Nothing needs recomputing to know the control's numbers: `lab show` / the trial row has them. What cannot be reused is the row: copying a curve into a new method's trial would duplicate it (D19 twin) and would not be a measurement. So "reuse" means citation by trial id in the pre-registration and the journal, not a row. Conditions under which the citation is a valid stand-in for a re-run: same window (dev), same rules/allocator/params (the child must compare), and the book was measured on the current research store. The store fingerprint matters: 1,192 dev trials sit on `640fc25e`, others on 3 older stores; a book recorded only on an older store has not been shown to reproduce on today's data.

**Compatibility, read from code.**
- *Append-only / frozen rows:* the change reads rows only; no write, no migration.
- *N policy:* N counts methods with a dev trial (`runner.run_method` comment, `twins` docstring). A method that cites rather than runs a control has fewer arms, not fewer methods; N is unchanged. A refused batch spends none either.
- *DSR:* `runner._dsr` uses the run's own arm moments plus the lab-wide trial Sharpe variance (`var_trials`). Fewer duplicate rows slightly change that variance for later methods; recorded rows and their stamped `moments` do not move.
- *Hard gate:* D17 reads control arms *within a method*; an arm with no resolvable control is UNRESOLVED and never refuses, and a method with no control is not refused. D19 refuses promoting an arm that is a twin of another method's book or of its own control; a cited control creates no such arm. A method whose only evidence needs a paired control in its own rows (walkforward, `lab control`) keeps declaring and running one.
- *`lab run` repeat refusal:* unchanged. It stays the guarantee; `lab idea`'s listing is a hint like the neighbour list.

## Current Dataflow

### Entry: `lab idea`
`engine/src/seer_engine/commands/lab.py:3999` `_idea` -> `store.next_method_id` + `store.add_method` in one IMMEDIATE transaction -> prints id to stdout -> `_print_idea_neighbours(conn, mid, text)` (`:3883`).

`_print_idea_neighbours` reads `methods` rows, ranks them with `_nearest_methods` (IDF-weighted cosine over name+family+hypothesis words, top `_IDEA_NEIGHBOURS`=5), prints to stderr. Wrapped in try/except so a hint never fails a made reservation.

### Reads available for the new listing
- `_roles(method_ids)` (`commands/lab.py:2890`): `(method, candidate) -> control_shape.role_of(arm)` from the method files via `discover()`; `{}` on any failure; 0.62 s for 5 methods measured here (first `discover()` ~1 s).
- `twins.twins_of(conn, candidate_id)` (`lab/twins.py:130`): other trials with the same window, trades and curve bytes, lowest `n` first; `.earlier` says whether it came first.
- `trials`: `n, method_id, candidate_id, rules_id, allocator_id, store_fingerprint, window` (schema read this session).

Prototype run (read-only, scratch) on M0606's idea text: neighbours M0610, M0108, M0522, M0528, M0091; controls found M0108-WORST20 (n 345, older store), M0528-REL-RAND (a twin of n 1236), M0091-HI5-N20-T (n 294, older store). So the listing is non-empty, a copy resolves to its first recording, and store status varies, which is why it is printed.

### Exit points
stderr only. No DB write after the reservation.
