## Detailed Requirements Understanding

**Problem.** "Explored before" has two meanings, and only one can be checked mechanically:

1. *The same idea in different words* (idea level). It can only be judged by reading, and two
   different descriptions can produce one book: M0538's "market-stripped losers" is M0028's
   "plain residual reversal", curve for curve. Wording similarity is neither necessary nor
   sufficient for a repeat.
2. *The same book* (book level). This is decidable: two arms that hold the same targets on every
   decision date have a byte-identical month-end `curve_json` and the same `trades`
   (`lab/twins.py` already defines a twin this way and reads it from the record).

The waste the owner objected to is a book-level fact, so the guarantee belongs at the book level.
Today it is detected only **after** the trials are recorded (`lab run`'s "Book twins" block,
`lab twins`, hardgate D19 at promote, calculate-assets), by which point the method has a dev trial
and therefore counts in N.

**The N fact that makes the cheap fix possible.** `store.DSR_POLICY = "methods"`: N is one per
distinct method **with a dev trial** (`lab/npolicy.py` docstring). A method whose `lab run` is
refused before `store.insert_trials` stays `idea`/`registered`, has no trial, and does not count.
So a refusal *inside* `lab run`, after simulation and before recording, costs no N and no extra
simulation. Measured on the committed DB this session: a repeat costs N +1 and a Sera slot only
because the trials get written.

**Pre-registration still holds.** `registry_problem` (`commands/backtest_dev.py:486`) only
requires the file to be committed and clean; `preflight` refuses only statuses past
`registered`. A method refused by the new check can be edited, re-committed (the new commit is the
new pre-registration) and re-run. The refusal must not print any arm's metrics first, or the
redesign would be made after seeing results.

**Success criteria.**
- `lab run` (and `lab run --amend`) exits 2, records nothing, and prints no metrics when an arm
  repeats a book **another method** recorded, unless that arm is a declared repeat.
- A declared repeat (a control arm by `control_shape.role_of`, or an arm whose rationale names the
  earlier trial's method id) still runs and is still labelled in the "Book twins" block.
- A batch in which **every** arm repeats a recorded book is refused even if all are declared:
  the method would measure nothing new (M0447).
- `lab idea` prints the nearest recorded methods by word overlap (stdlib, no network), so the
  reserving agent sees likely repeats before spending an id. It never refuses.
- The Sera and explore skills tell the agents what to do on the refusal, with no owner step.

**Edge cases.**
- Twin of an earlier arm of the **same** method (amendment repeating an original, a treatment
  equal to its own control in this batch): not a cross-method repeat; stays an annotation
  (existing `report_lines` "treatment never acted" flag).
- Cross-store: compared by curve bytes regardless of store fingerprint, as `twins.py` does.
  A recorded book on an older store whose prices moved will not match (a false negative,
  accepted: the record cannot say they are the same book).
- Near-twins (one trade different over 20 years) are out of scope: not byte-identical.
- `role_of` reads prose; an arm mislabelled as control escapes the refusal. Accepted: the label is
  pre-registered, and the Book twins block and D19 still report it.

**Assumptions.** Monthly `curve_json` + `trades` is the twin definition (unchanged). The refusal is
a `store.LabError` (exit 2: the lab's rules refused). No schema change, no new table, no
dependency.

## Current Dataflow

### Entry Point: `python -m seer_engine lab run MNNNN [--amend]`

**Location:** `commands/lab.py:_run` (l.1918) → `runner.run_method` (l.656)

1. `runner.preflight` (l.261): commit check (`registry_problem`), real-fee check, status check
   (`idea`/`registered` only, or `--amend` rules), parent present, and the **digest** repeat check
   `store.has_trial(conn, config_digest(c), "dev")` (l.331). A wrapper allocator or params class
   moves the digest, so this never catches a repeated book (twins.py docstring).
2. `dev.run_registry(...)` simulates every candidate; `on_result` (l.710) appends
   `(row, month_end_curve(result.snapshots))` and **logs each arm's money-weighted return, max DD,
   PF and trades at INFO as it finishes** (l.715).
3. `store.begin_immediate(conn)`; inside `with conn:` the preflight is repeated
   (`require_commit=False`), `trial_rows` builds `TrialRow`s with
   `curve_json=store.curve_json(curve)` and `trades=int(met.trades)` (l.628, l.641), then
   `store.add_method`/`update_method`, `insert_trials`, moments, funding, provenance, folds,
   status, `mark_seen`.
4. Back in `_run`, after the transaction: verdict blocks, mirror pairs, then the **Book twins**
   block reads `twins.for_method(conn, method.id)` on the rows just written (l.2132-2156) and
   prints `twins.report_lines` with roles from `_roles_by_candidate`.

### Entry Point: `lab idea --name --family --hypothesis --source-kind [--source-ref] [--parent]`

`commands/lab.py:_idea` (l.3810): `begin_immediate`, `next_method_id`, `add_method(status='idea')`,
prints the id. No look at existing methods.

### Data Persistence
`lab/lab.sqlite` `trials` (append-only by trigger; `curve_json`, `trades`, `window`, `n`
AUTOINCREMENT), `methods` (status machine `store.TRANSITIONS`).

### Exit Points
Exit 0 on a recorded run; `store.LabError` → exit 2 (`commands/lab.py` l.1005-1007).
