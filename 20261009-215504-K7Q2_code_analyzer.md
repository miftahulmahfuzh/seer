## Detailed Requirements Understanding

**Problem.** `hardgate.failed_kin` (`hardgate.py:777`) is the one definition of kin. It unions three name/record-based links: the `family` string, transitive `parent_id` ancestors (`_lineage`, `:733`), and engines named `<MNNNN>` in a dev trial's `config_text` together with their lineage (`ingredients`, `:753`). Nothing in it looks at what a method's books actually do. A plain 12-1 momentum book filed under `stock-low-volume-momentum` with parent M0057 (rejected, short-term momentum) touches none of those links to M0002 (test-failed, `stock-momentum-risk-managed`), M0022 (test-failed, `stock-residual-momentum`) or M0021/M0029 (test-failed, `stock-multi-factor-blend`).

**Success criteria.**
1. `failed_kin` additionally links a method to every test-failed method whose tested variant's de-funded, beta-adjusted monthly returns correlate with any of the method's dev variants at or above a measured threshold.
2. A plain momentum book (the lab's recorded proxy: seed `H-P7A-F4`'s `F4-MOM12-N20-TREND`, exactly the F4-MOM12 book M0060's hypothesis names) is linked; non-momentum books (index timing, sector rotation, low-vol, RSI(2), turn-of-month, fundamentals, illiquidity) are not.
3. `lab status` still prints `Promotable now: (none)`.
4. D14 in the docstring states options, measurements, choice, the no-curve behaviour, and D13's status.
5. M0060/M0062 rows handled and recorded.
6. Skill's kin text matches the rule.

**Key considerations.**
- Method files that have run are **frozen** (`source_sha`; `tests/test_lab_methods.py::test_a_method_that_ran_is_frozen`, `prereg`, `runner.preflight`). All four test-failed methods ran, so option (a) "a field in the method files" cannot be written onto the very methods kin has to point at.
- `runner.py:446-452`: when an `idea` row runs, the runner overwrites `family` (and name, parent, source) from the method file. A re-filed idea row's family lasts only as long as the child that writes the file copies it.
- `store.update_method` (`store.py:741`) allows `family`; no trigger guards `family` (`methods_hypothesis_frozen` guards only `hypothesis`, `methods_status_forward` only `status`). Updating an idea row's family is permitted.
- Fixture curves in `tests/test_lab_hardgate.py` are constant-growth (`_curve(months, annual)`), so their monthly returns have zero variance: correlation is undefined. The new code must treat a zero-variance series (method, failed, or benchmark) as *not measured*, never as kin, never as a crash or a NumPy warning.
- Fixture test-failed methods have **no** test trial. The behavioural side must skip a failed method with no recorded test trial, otherwise every existing kin test changes.

**Assumptions (stated, planned against).**
- "M0060/M0062-shaped" is read as the *filing shape* (plain momentum book, new family, non-momentum parent). The measured proxy for a plain momentum book is `H-P7A-F4` (0.97). M0062's 12-1 pick inside the 60 most liquid names has no recorded curve; under (b) its own curve decides at promotion.
- "Promoted variant" in the prompt is widened to **every dev variant** for the method side, for the same reason D12 gave (measured below; it refuses nobody new).

## Current Dataflow

### Entry point: `lab promote MNNNN`
`commands/lab.py:_promote` → `hardgate.check(conn, mid)` (`hardgate.py:856`) → silent unless `dev-eligible` → `geometry` → `fold_record` (picks) → `promoted_variant` + `variant_record` (D11) → `failed_kin` → raise `LabError` naming the kin → else `prereg.promote_method`, whose file records `family_state` (`prereg.family_text` → `failed_kin`).

### `failed_kin(conn, mid)` (`hardgate.py:777`)
1. `store.get_method`; unknown → `LabError`.
2. `_lineage(row)` = ancestors via `parent_id` ∪ all ids with the same `family`.
3. For each `ingredients(conn, mid)` (regex `<(M\d{4})>` over dev `config_text`, filtered to known ids, self excluded): add it and its `_lineage`.
4. Discard self; `SELECT id ... status='test-failed'` over the set; sorted tuple.

### Other readers of `failed_kin`
- `family_state` → `summary` (`lab status`, lenient) and `prereg.family_text` (never raises).
- `runner.py:569` — `lab test`'s note (information only, D3).
- `commands/lab.py:2055` — `lab walkforward` passes `", ".join(kin)` to `wf.buy_signal` as `family_failed` (D9/D13). **No try/except**: any new `LabError` from `failed_kin` would kill the report.

### Curves
`trials.curve_json` — list of `[iso_date, value]`, one point per month (`regime.month_ends`), normalised to opening cash. Funded trials: `trial_deposits(conn, row, curve)` → per-step deposit units; `regime.defunded(curve, deposits)` → value series without deposits. Benchmark: first `REF-SPY-HOLD` dev trial (`geometry`), never funded. Comparability: `mismatches(conn, bench_n, rows)` on `trial_provenance.price_fingerprint` (D10).

### Data persistence
Read-only for the gate. Idea re-filing (R3) is `UPDATE methods SET family=?, updated=?` through `store.update_method` on the main checkout's `lab/lab.sqlite`, then `lab stage` (`git add` of db + `web/data/lab.json` under `BEGIN EXCLUSIVE`).
