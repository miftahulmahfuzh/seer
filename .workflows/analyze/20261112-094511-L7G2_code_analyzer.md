## Detailed Requirements Understanding

**Problem/Requirement Statement:** The leaderboard chart's legend is a static `<span>` list rendered twice by a server component (desktop in the headline row pushed right by `margin-left: auto`; mobile under the axis). It must move to a left-aligned row and become interactive toggles driving a line-highlight state, which a card pick (URL `?s=`) also feeds.

**Success Criteria:** the R table above.

**Key Considerations:**
- `page.tsx` is an async server component (`force-dynamic`); interactivity needs a `'use client'` component. A card is a `<Link href="/leaderboard?s=X" scroll={false}>` — a soft navigation, so a client component at the same tree position keeps its state and receives the new pick as a prop. That is what makes "add" work: on a pick change, add the new id to the existing set.
- Both legends (desktop + mobile) must share one state, so the client component owns the svg and both legends.
- Pill padding must not shift the first swatch off the alignment edge: every item always carries the padding, and the row takes a matching negative inline margin.
- SPY's look tint is `var(--sheet)`, invisible on the white chart sheet; its active pill needs `var(--chip-plain)` (the same substitution `.card:global(.bg-sheet) .icon` uses).
- CLAUDE.md "every button is icon-only": the legend toggles carry text by necessity (the code is how lines are told apart); the owner accepted this in the discussion turn.
- Assumption: hovering is not asked for; no hover preview.
- Assumption: highlight transitions are short opacity fades, disabled under `prefers-reduced-motion`.
