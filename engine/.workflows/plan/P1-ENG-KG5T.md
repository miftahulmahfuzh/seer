## Goal

The `backtest` command built by phases 1–5 is run once for real against Neon (read-only). Its
report, equity CSV and SVG are committed under `docs/backtests/`. `STRATEGY_A_PARAMS` holds the
parameters the in-sample grid selected, written as an explicit `AParams(...)` literal with a
comment naming the report. A new test fails if the code's frozen parameters ever drift from the
committed report. The engine readme documents the strategy interface, the backtest and the
report, and ROADMAP P3 states the gate verdict, including "P4 must not start" when the gate
failed. A failing gate is still a successful phase: the job is to measure honestly, not to win.

Most of this phase is operations (runs, byte-identity checks), not code. The only source edit is
one constant and its comment. The only new code is one test file.

## Rules for this phase (read before Step 1)

1. **Never tune on out-of-sample.** Do not pass `--is-start`, `--oos-start`, `--end` or
   `--dividends`; run with defaults only. Do not edit the grid, the windows, the selection rule,
   the gate, any strategy rule, costs or the simulator to change a number. Do not look at OOS
   numbers and then re-run anything with different settings.
2. **Never hand-edit a generated file.** If a report file is wrong, the code is wrong: fix the
   code (Bug protocol) and regenerate.
3. **Commit locally only.** The repo is public; `git push` needs the owner's explicit consent in
   the conversation. This phase never pushes.
4. **Never `source` `.env.local`** (unquoted `&`). Point the engine at it with `SEER_ENV_FILE`.
   Never run raw `psql` against Neon from WSL (IPv6 hang); use the engine.
5. **One sitting.** Runs #1–#3 must see the same Neon data. If the bars fingerprint
   `(max(date), count(*))` changes between Step 1's preflight and Step 6's post-check (a nightly
   run landed), throw away every output and restart at Step 2 (Step 3 is undone too: put
   `STRATEGY_A_PARAMS` back to `DESIGN_PARAMS`).

### Neon unreachable

If the preflight (Step 1c) or any run fails to connect (`psycopg.OperationalError`, timeout,
DNS, `ConfigError` for `DATABASE_URL_UNPOOLED`): **stop.** Do not commit anything from this
phase, do not write a report by hand, do not run the command against any other database, do not
put placeholder files in `docs/backtests/`. Leave `STRATEGY_A_PARAMS = DESIGN_PARAMS`. Report to
the caller: the exact command, the exit code, the last 30 lines of the log, and that phase 6 is
blocked on Neon access. Retrying later from Step 1 is fine; the cache in `engine/.cache/` (if
run #1 got that far) is reused automatically.

### Bug protocol

A **bug** is a crash, a raised exception, or output that contradicts the plan index's interface
contract or **Decisions** table (for example a negative share count, a curve that does not start
at `prev_session(start)`, a report section missing, a run that is not byte-reproducible). A
result you do not like is never a bug. When the real run exposes one:

1. Stop. Write a failing regression test in the owning phase's test file that reproduces it on
   synthetic data.
2. Fix it in the owning module (phases 1–5 own them; see `Leaves alone`). Change nothing else.
3. Run the full suite (Step 7 command).
4. Commit the fix on its own, before the report commit, with a message that says it was found by
   the real run and what it changed:
   `fix(backtest): <what> (found by the P3 real run)` and a body describing the symptom, the root
   cause, and whether it changes any reported number.
5. Delete `docs/backtests/<END>-strategy-a*` and restart at Step 2. The bar cache may be kept.

If the fix would require changing a rule, the grid, the windows or the simulator, it is not a
bug-fix: stop and report to the caller instead.

**Grid wall time.** If the logged total grid time exceeds 60 minutes, the run's result is still
valid (parallelizing changes no number). Record the time in the readme and add a handoff; do not
parallelize in this phase.

### Step 3: Freeze the selection in code

**File:** `engine/src/seer_engine/strategies/a.py`, the `STRATEGY_A_PARAMS` line written by phase 1
directly after `DESIGN_PARAMS = AParams()` (locate with `grep -n "STRATEGY_A_PARAMS" engine/src/seer_engine/strategies/a.py`).

**Change:** replace phase 1's line (and any comment phase 1 put directly above it about phase 6)
with an explicit literal of the **selected** parameters, read from the run #1 report's
`selected-params:` line. Always write the literal, even when the selection is the design fallback,
so a later edit to `DESIGN_PARAMS` can never silently change the frozen strategy.

Value mapping from the JSON. `as_dict()` renders every value as a **normalized** plain decimal
string (phase 1: `Decimal("1.0")` → `"1"`, `Decimal("2.0")` → `"2"`, `5.0` → `"5"`), so the JSON
never shows a trailing zero. Write each value in the spelling of the grid constant it came from
(`tuning.GRID_*`), which is how the selection's `AParams` was built:
`rsi_max` → float literal (`"5"` → `5.0`, `"15"` → `15.0`);
`limit_atr` → `Decimal("0.25")`, `Decimal("0.5")` or `Decimal("0.75")`;
`tp_atr` → `Decimal("0.75")`, `Decimal("1.0")` (JSON `"1"`) or `Decimal("1.5")`;
`sl_atr` → `Decimal("1.0")` (JSON `"1"`), `Decimal("1.5")` or `Decimal("2.0")` (JSON `"2"`);
`min_dollar_volume` → `20_000_000.0` (JSON `"20000000"`; the grid never varies it).
Either spelling round-trips: `as_dict()` normalizes, and `AParams` equality compares Decimals by
value (`Decimal("1") == Decimal("1.0")`), so the report's "matches the selection" check and the
frozen test agree whichever is written; the grid spelling is required only for readability.

**Code** (fill the four bracketed values from the report; the template shape is exact — every
other character stays as written):

```python
# Frozen by P3 (Strategy A + 10-year backtest), run on Neon data through <END>.
# Selected by the fixed 81-run grid on the IN-SAMPLE window 2015-10-19..2021-12-31 only:
# highest in-sample total return among runs with max drawdown <= 15% and profit factor >= 1.3
# (DESIGN_PARAMS when none qualifies). The out-of-sample window 2022-01-03..<END> was run once
# with these values and never tuned on. Gate verdict: <PASSED|FAILED>.
# Report: docs/backtests/<END>-strategy-a.md
# tests/test_strategy_a_frozen.py fails if these drift from that report's frozen-params line.
# Changing any value resets the forward clock: re-run `seer_engine backtest` and commit its report.
STRATEGY_A_PARAMS: AParams = AParams(
    rsi_max=<RSI>,
    limit_atr=Decimal("<LIMIT>"),
    tp_atr=Decimal("<TP>"),
    sl_atr=Decimal("<SL>"),
    min_dollar_volume=20_000_000.0,
)
```

For example, if the report says
`selected-params: {"rsi_max": "5", "limit_atr": "0.25", "tp_atr": "1", "sl_atr": "2", "min_dollar_volume": "20000000"}`,
the body is `rsi_max=5.0, limit_atr=Decimal("0.25"), tp_atr=Decimal("1.0"), sl_atr=Decimal("2.0")`.

If the gate FAILED, still freeze the selection (plan index **Decisions**: "Frozen params when the
gate fails").

Then verify: `engine/.venv/bin/python -c "from seer_engine.strategies.a import STRATEGY_A_PARAMS as p; import json; print(json.dumps(p.as_dict()))"`
must print exactly the JSON of the report's `selected-params:` line.

**Impact:** changes only what the report records as frozen. The OOS and full-window runs use
`report.selection.params`, so no reported number moves. P4 will read this constant.

### Step 4: Add the frozen-params test

**File:** `engine/tests/test_strategy_a_frozen.py` (new).

**Code:**

```python
"""The parameters frozen in code are the ones the committed backtest report selected.

P3 (handover §3 "Frozen parameters"): Strategy A's parameters are tuned on the in-sample window
only, then frozen in ``seer_engine.strategies.a.STRATEGY_A_PARAMS`` with a comment naming the report
that froze them. ``report.render_markdown`` writes two machine-readable lines into that report:

    frozen-params: {"rsi_max": "...", ...}     # STRATEGY_A_PARAMS.as_dict() at run time
    selected-params: {"rsi_max": "...", ...}   # the in-sample selection's as_dict()

``report.parse_params_line`` reads them back. These tests read the newest committed
``docs/backtests/*-strategy-a.md`` and fail when the code, the report's frozen line and the
report's selection disagree, so the frozen strategy can never drift from the evidence without a
new report being committed.
"""

from __future__ import annotations

from pathlib import Path

import seer_engine.strategies.a as strategy_a
from seer_engine import config
from seer_engine.backtest.report import FROZEN_KEY, SELECTED_KEY, parse_params_line
from seer_engine.strategies.a import STRATEGY_A_PARAMS

BACKTESTS_DIR = config.REPO_ROOT / "docs" / "backtests"
REPORT_GLOB = "*-strategy-a.md"


def _latest_report() -> Path:
    reports = sorted(BACKTESTS_DIR.glob(REPORT_GLOB))
    assert reports, f"no committed Strategy A report matches {BACKTESTS_DIR / REPORT_GLOB}"
    return reports[-1]  # stems start with the ISO data-end date, so name order is date order


def test_code_params_equal_report_frozen_params() -> None:
    report = _latest_report()
    frozen = parse_params_line(report.read_text(encoding="utf-8"), FROZEN_KEY)
    expected = STRATEGY_A_PARAMS.as_dict()
    assert list(frozen.items()) == list(expected.items()), (
        f"STRATEGY_A_PARAMS {expected} differs from {report.name} {FROZEN_KEY} {frozen}; "
        "re-run `python -m seer_engine backtest` and commit its report, never edit either by hand"
    )


def test_report_froze_its_own_selection() -> None:
    report = _latest_report()
    text = report.read_text(encoding="utf-8")
    frozen = parse_params_line(text, FROZEN_KEY)
    selected = parse_params_line(text, SELECTED_KEY)
    assert list(frozen.items()) == list(selected.items()), (
        f"{report.name}: {FROZEN_KEY} {frozen} is not the in-sample selection {selected}; "
        "set STRATEGY_A_PARAMS to the selection and re-run the backtest"
    )


def test_frozen_params_comment_names_the_report() -> None:
    report = _latest_report()
    source = Path(strategy_a.__file__).read_text(encoding="utf-8")
    assert f"docs/backtests/{report.name}" in source, (
        f"the comment above STRATEGY_A_PARAMS in {Path(strategy_a.__file__).name} must name "
        f"docs/backtests/{report.name}"
    )
```

Notes for the implementer:
- `config.REPO_ROOT` resolves from the installed package's file location, so in this worktree it
  is the worktree, and in CI it is the checkout. Both contain `docs/backtests/`.
- No test here skips: a missing report is an assertion failure, which is intended (CI fails on
  `SKIPPED` and must also fail on a missing report).
- Running this test **before** run #2 must fail `test_report_froze_its_own_selection` and
  `test_code_params_equal_report_frozen_params` (the run #1 report still says the design values
  are frozen), unless the selection was the design fallback. Run it once now to see that
  (`PG_TEST_URL=... engine/.venv/bin/pytest engine/tests/test_strategy_a_frozen.py -q`); this is
  the test's red step.
- The line format is phase 4's (reconciled): parse only through `report.parse_params_line` with
  `FROZEN_KEY` / `SELECTED_KEY`, never a second regex. The reconciler ran these three tests against a
  report rendered by phase 4's code with a literal `STRATEGY_A_PARAMS` naming it: 3 passed.

**Impact:** new test file; no source change.

### strategies (P3)

Pure, like `sim`: no database, network, clock, randomness or logging, and never `bars`.
`tests/test_strategy_purity.py` globs every module in `strategies/` and `backtest/` (except
`backtest/io.py`) and checks this in a subprocess and on the AST. P4 calls this code nightly and
P6 adds strategies B and C beside `a.py`.

**`strategies.base`**
- `@dataclass(frozen, slots) History(symbol, dates, open, high, low, close, volume)`: one symbol's
  daily bars, ascending, one row per bar it has (gaps allowed). `dates` is `datetime64[D]`; the
  rest are float64 arrays of the same length. `len(h)`, `h.upto(d)` (bars dated `<= d`, a view),
  `h.last_date()`, `h.index_of(d)` (row of the bar dated `d`, else `None`).
- `history_from_bars(symbol, bars: Sequence[Bar]) -> History`: `float(Decimal)` per field.
- `Strategy` protocol: `id: str`, `lookback: int` (bars per symbol `picks` needs), and
  - `picks(history, members, data_date, params) -> list[Pick]`: the nightly entry point. `history`
    maps symbol → `History` through `data_date`; longer histories are fine, only the last
    `lookback` bars dated `<= data_date` are read.
  - `prepare(history) -> Any` and `picks_prepared(prepared, members, data_date, params)`: the
    backtest's fast path, computing parameter-independent features once for every date.
  - **Contract:** `picks_prepared(prepare(H), M, d, p) == picks({s: h.upto(d)}, M, d, p)` for
    every `d`. A test proves it on a multi-symbol synthetic set.

**`strategies.indicators`** — window functions take 2-D float64 arrays shaped `(rows, W)`, oldest
column first, and return one float64 per row, `NaN` when `W` is too short. They use only
elementwise numpy and an explicit loop over columns (never a reduction along time), so a row's
result is bit-identical whatever the number of rows.
- `sma_window(close, n)`: the last `n` closes summed left to right, `/ n`.
- `wilder_rsi_window(close, n)`: changes `d_i = c_i − c_{i−1}`; seed = mean of the first `n` gains
  and losses; then `avg = (avg·(n−1) + x) / n`; `100` when the average loss is 0, else
  `100 − 100 / (1 + avgG/avgL)`.
- `wilder_atr_window(high, low, close, n)`: `TR = max(h − l, |h − c_prev|, |l − c_prev|)` from the
  window's second bar; seed = mean of the first `n` TRs; Wilder after.
- `mean_dollar_volume_window(close, volume, n)`: mean of `close × volume` over the last `n` bars.
- `rolling(fn, *series, window, **kw)`: a length-T series → length-T result via
  `sliding_window_view`, `NaN` for `t < window − 1`.

**`strategies.a`** (design §4)
- `LOOKBACK = 200`, `SMA_N = 200`, `RSI_N = 2`, `ATR_N = 14`, `DV_N = 20`.
- `@dataclass(frozen, slots) AParams(rsi_max=10.0, limit_atr=Decimal("0.5"), tp_atr=Decimal("1.0"), sl_atr=Decimal("1.5"), min_dollar_volume=20_000_000.0)`;
  `as_dict() -> dict[str, str]` in a stable key order (what P4 writes to `strategies.params`).
- `DESIGN_PARAMS = AParams()`: design §4's starting values, the selection fallback.
- `STRATEGY_A_PARAMS`: **the frozen parameters**: `{{FROZEN_JSON}}`, selected on the in-sample
  window only by the committed report `docs/backtests/{{END}}-strategy-a.md`.
  `tests/test_strategy_a_frozen.py` fails if code and report disagree. Changing a value means
  re-running the backtest and committing its report, and it resets the forward clock.
- `features_at(history, data_date) -> list[Features]` (sorted by symbol) and
  `picks_from_features(features, members, params) -> list[Pick]`; `StrategyA` implements
  `Strategy` with `id = "A"`, `lookback = LOOKBACK`; `STRATEGY_A = StrategyA()`.

| Rule | Strategy A |
|---|---|
| Timing | Picks for session S use bars through `data_date = prev_session(S)` only; `last_price` = that close. Every indicator is a function of the symbol's last 200 bars ending at `data_date`, Wilder recursions seeded inside that window, so the backtest and the nightly job compute bit-identical floats |
| Eligible | member on `data_date` (point-in-time), a bar dated `data_date`, ≥ 200 bars through it |
| Setup | `close > SMA200` and `RSI(2) < rsi_max` and 20-day mean `close × volume > min_dollar_volume`, all strict |
| Prices | `last = to_decimal(close)`, `atr = to_decimal(ATR14)`, `limit = q(last − limit_atr·atr)`, `tp = q(limit + tp_atr·atr)`, `sl = q(limit − sl_atr·atr)` |
| Dropped | after `q`: `last ≤ 0`, `limit ≤ 0`, `sl ≤ 0`, `sl ≥ limit` or `tp ≤ limit` (`Pick` would raise); dropped silently, never raised |
| Ranking | `(rsi, symbol)` ascending; every qualifying candidate is returned. Held symbols are not filtered: `size_picks` rejects them as `held` without using a slot |

**Float vs Decimal.** Indicators and the setup comparisons are float64; everything handed to the
simulator is a 4-dp `Decimal`. `bars.close` is `numeric(12,4)` (at most 12 significant digits), so
`to_decimal(float(close))` round-trips exactly through `repr`. A float could flip a strict
threshold only within about 1e-12 of it (RSI exactly 10.0 is excluded by `<`), and because the
window math is bit-identical, it flips the same way in the backtest and nightly.

the database.

- **`backtest.market`**: `Membership(intervals)` with `members_on(d) -> frozenset[str]` (both
