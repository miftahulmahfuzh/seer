## Detailed Requirements Understanding

**Problem/Requirement Statement.** The desktop leaderboard row is built from "decks" (`stacks()` in `view.ts`). An original and its Claude twin share one grid cell, with the twin tucked behind and peeking out. Picking either card opens the whole deck, so both cards fan out, rise 10px and scale 2%. The owner wants this replaced with one flat row of overlapping cards, stacked left over right. A click brings the clicked card to the front without moving anything. Twins become ordinary cards.

**Success criteria.** The criteria above, plus `npx tsc --noEmit` and `npm test` green, and the verify-seer leaderboard entry and its desktop step updated in the same commit (CLAUDE.md feature-map rule).

**Key considerations and assumptions.**
- *Left covers right hides each card's left 40%.* Under left-over-right stacking, card *i*'s left 40% sits under card *i−1*. In the current markup the code, chips and total return are on the left, so on every card but SPY and the front card they would be hidden. The prototype the owner approved hid them in exactly this way. R1.3 makes "readable" explicit, and the plan meets it by mirroring the card's contents on the desktop row: the icon goes to the top-left and the code, chips, return and metrics are right-aligned (Decision D1).
- *SPY above the pick (R2.2).* The owner's reason for left-covers-right is "always see the baseline: SPY". If the front card rose above SPY, C (index 1) would cover SPY's right 40%, where the mirrored code and return now sit. So SPY stays the topmost card even when another card is picked. SPY is not clickable (an `<article>`, never a pick), so it never competes for the front.
- *The picked card covers its left neighbour's right side.* A card raised in place above its left neighbour covers that neighbour's right 40%. When that neighbour is not SPY, it shows only its middle 20% while the pick is in front. It keeps its name as a tooltip (`data-tip`). This follows directly from "brought to the top" plus "fixed in position", and the owner will see it in the screenshots.
- *The tab stays.* The picked card is still the tab that meets the month-by-month sheet (square bottom, fillets, `data-tab`/`data-edge`), because R3.3 says the panels keep working "exactly as today". The front card's shadow is cast up and to the sides only, never down onto the sheet. The old code had no shadow on the tab for the same reason.
- *Mobile and the retired shelf are out of scope.* Every new rule sits in the `min-width: 1024px` block. The shelf's grid `--cols` becomes `live.length` (it used to count decks).
- `stacks()` has one consumer, `page.tsx`, so it and its tests are deleted. `attachedOriginal` / `orderTwins` stay: `components/roster.ts` and `lib/data.ts` use them, and `orderTwins` already puts each twin right after its original, so the flat row is just `live` in its existing order.

## Current Dataflow

### Entry Point: `GET /leaderboard?s=<id>`
**Location:** `web/app/(app)/leaderboard/page.tsx:30` (`Leaderboard`, a server component, `force-dynamic`)
**Input:** `searchParams.s`, the picked strategy id.
**Next step:** `leaderboard()` and `runStatus()` from `lib/data`. `board.rows` is ordered by `orderTwins`.

### Processing Chain
1. `live = board.rows.filter(not retired)` (`page.tsx:45`).
2. `pick = pickResearch(research, q.s)` (`:67`). SPY is never a pick.
3. `decks = stacks(live)` (`:191`). `ids = decks.flat()` gives `tabEdge` ('first' / 'last' / undefined) (`:193`).
4. `isOpen(rows)` means "the deck holds the pick" (`:195`). `rowCols` = Σ (open ? deck length : 1) (`:198`), passed to `RetiredShelf cols`.
5. `monthsSheet` gets `data-tab={tabEdge}` (`:200`).
6. Render: `<div className={s.cards}>{decks.map(deck)}</div>` (`:236`).
7. `deck(rows)` (`:257`): `<div class=deck data-deck data-open style=--n>` around `card(r, true, {depth, open})`.
8. `card(row, tab, place)` (`:274`): `tucked` = depth > 0 and the deck is closed, which renders a `.peek` strip and sets `aria-label`. The class is `sheet over <bg> card [cardActive|cardPicked]`. The style is `--tint` and `--depth`. SPY renders as `<article>`, others as `<Link href=/leaderboard?s=id scroll={false}>` with `aria-current` and `data-edge`.

### CSS (≥1024px), `leaderboard.module.css`
- `.cards` (`~L172`): `display:grid; grid-auto-flow:column; grid-auto-columns:minmax(0,1fr); gap:12px; container: cards`.
- `.cardActive` (`~L194-216`): the tab (square bottom, `margin-bottom:-12px`, fillets via ::before/::after, `data-edge` squares the row's ends; `.months[data-tab]`).
- `.deck`, `.deck > .card`, `.deck:not([data-open]):hover`, `.peek`, `.deck[data-open]`, `.deck[data-open] > .card` (translateY(-10px) scale(1.02), shadow), `.deck[data-open] > .cardActive` (`~L242-285`).
- `.deck .name/.nameText/.chips` (`~L289-294`): codes shown whole.
- Reduced motion for `.deck > .card` (`~L298-300`). `@container card (max-width:200px) .deck .name` (`~L315-317`).
- Below 1024px: `.deck {display:contents}`, `.peek {display:none}` (`~L81-90`).

### Exit Points
HTML only. No writes. A click is a client-side navigation to `?s=`, and the server re-renders with the new pick.
